# Skill Guidelines

很多 skill 的通病：
- **废话多**——写入过多模型已知细节，不仅费Token和上下文，而且会稀释核心指令；
- **要求高**——过于复杂的执行流程和模糊指令，导致只有顶级模型才能正常跑完，经济型模型难以跑完全程，且最终结果相去甚远；
- **说得漂亮**——读起来头头是道，跑起来跳步、空转、不执行。

本技能用 11 条原则对症治理这些问题，分四层：

| 层 | 原则 |
|----|------|
| 一 · 通用 Cross-Cutting | 1 想清楚再动手 · 2 最小充分 · 3 避免过度内耗 |
| 二 · 结构 Structure | 4 模块化复用（DRY） · 5 渐进式披露 |
| 三 · 流程 Flow Control | 6 交付物锚定 · 7 优雅降级 · 8 推进必过门 |
| 四 · 编写 Craft | 9 张弛有度 · 10 解释为什么 · 11 示例胜于说教 |

元规则：两条原则冲突时，优先保障输出准确性，其次可维护性，最后简洁。

## 亮点

- **交付物锚定**：用"产物是否存在、是否通过校验"核查进度，替代模型"我做完了"的自述；给出过程产物是否落盘的三条件判定，并附完整链条示例。
- **反内耗四诊断**：把思考链空转定位为四类结构性缺陷——互斥指令、分支不互斥、条件不可判定、循环无上限——各配按优先级排序的消解方案。
- **尽力与降级绑定**：区分环境性故障（变化着重试）与能力性故障（直接降级不傻重试）；降级必须留痕。次优结果 > 报错 > 死循环。
- **机门 / 人门分工纪律**：门控外化推进条件——可机械验证的不交给人（审批不退化为噪声），需人拍板的不交给机器（schema 合法 ≠ 决策正确）；🔴 标记只用于不可逆操作。
- **张弛有度**：松紧由任务性质决定——"能为正确结果写出检验器的"交给脚本与枚举，开放判断留给模型，拒绝整篇一刀切。

## 使用

将本目录整体放入支持 SKILL.md 规范的 Agent 技能目录即可：

```
WorkBuddy:    ~/.workbuddy/skills/skill-guidelines/
Kilo:         ~/.kilo/skills/skill-guidelines/
Claude Code:  ~/.claude/skills/skill-guidelines/
```

创建、审查或优化 skill 时，通过技能名 `skill-guidelines` 触发加载。
